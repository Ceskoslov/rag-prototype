NAMED VOLUMES CONFIGURATION:
----------------------------

All critical data stores use Docker named volumes for persistence:

1. POSTGRES DATA (postgres_data):
   - Mount: postgres_data:/var/lib/postgresql/data
   - Contains: User accounts, conversation checkpoints, session metadata
   - Driver: local
   - Survives: docker compose down (unless --volumes flag used)

2. REDIS DATA (redis_data):
   - Mount: redis_data:/data
   - Contains: Parent document cache, ARQ job queue, BM25 docstore
   - Driver: local
   - Survives: docker compose down (AOF persistence enabled)

3. CHROMA DATA (chroma_data):
   - Mount: chroma_data:/chroma/data
   - Contains: Vector embeddings, child chunks, semantic index
   - Driver: local
   - Survives: docker compose down

RESTART POLICIES AND PERSISTENCE INTERACTION:
----------------------------------------------

Service restart policies ENHANCE persistence by ensuring containers auto-recover:

1. postgres (restart: unless-stopped):
   - Container restarts automatically if it crashes
   - postgres_data volume remains intact across restarts
   - No data loss even if Postgres daemon fails

2. redis (restart: unless-stopped):
   - AOF (Append-Only File) writes to redis_data volume
   - Container restarts automatically
   - Data survives both container restarts AND daemon crashes

3. chromadb (restart: unless-stopped):
   - SQLite database in chroma_data volume
   - Container restarts automatically
   - Vector index persists across restarts

4. api, worker, frontend, nginx (restart: unless-stopped):
   - Stateless services (no persistent data)
   - Auto-restart ensures service availability
   - Connects to persisted data in postgres/redis/chroma

5. seed (restart: "no"):
   - INTENTIONALLY does NOT restart
   - Only runs once per environment lifecycle
   - Re-running would duplicate data in ChromaDB
   - To re-seed: manually start with `docker compose up seed` after clearing volumes

NAMED VOLUMES vs BIND MOUNTS:
------------------------------

Production (docker-compose.yml):
- Named volumes: postgres_data, redis_data, chroma_data
- Benefits:
  ✓ Docker manages volume lifecycle
  ✓ Survives container removal
  ✓ Optimized for container I/O performance
  ✓ Easy to backup/restore via `docker volume` commands

Development (docker-compose.dev.yml):
- Bind mounts: ./apps/backend:/app, ./apps/frontend:/app
- Benefits:
  ✓ Code changes immediately visible in container
  ✓ Enables hot reload during development
  ✓ No need to rebuild on every change
- Named volumes still used for data (postgres_data, etc.)
