WHY THESE DIRECTIVES MATTER:
-----------------------------

1. proxy_buffering off:
   - Disables Nginx's default response buffering behavior
   - Without this, Nginx waits for entire response before sending to client
   - Critical for SSE: events must stream incrementally, not batch

2. proxy_read_timeout 300s:
   - Default is 60s, causing connections to close during long streaming
   - 300s (5 minutes) allows for extended thinking/generation time
   - Prevents premature timeout during multi-agent reasoning

3. X-Accel-Buffering: no:
   - Extra layer of buffering protection specific to Nginx
   - Some Nginx versions ignore proxy_buffering for certain content types
   - This header ensures FastAPI's "Transfer-Encoding: chunked" is respected

4. proxy_http_version 1.1:
   - Required for HTTP/1.1 chunked transfer encoding
   - SSE relies on chunked encoding for incremental delivery
   - HTTP/1.0 doesn't support streaming responses

5. CORS OPTIONS handling:
   - Allows browser-based frontend to make cross-origin SSE requests
   - Returns proper preflight response for OPTIONS requests
   - Now consistent in both HTTP and HTTPS blocks

KEY OBSERVATION: Events arrive incrementally (line-by-line), NOT as a single buffered blob.

WITHOUT THESE DIRECTIVES (broken behavior):
--------------------------------------------
- Client sees nothing for 10-30 seconds
- Then receives ALL events in one giant batch
- Defeats the purpose of streaming UX
- User perceives system as "frozen" then suddenly responsive

WITH THESE DIRECTIVES (correct behavior):
------------------------------------------
- First event arrives within 1-2 seconds
- Each token appears as it's generated
- User sees "thinking in progress" feedback
- Matches ChatGPT-style streaming experience
